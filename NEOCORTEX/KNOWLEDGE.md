## Core Rules (non-negotiable)

### RULE#1 Faithful to the source
Summarize; don't embellish or interpret. Quotes are verbatim with attribution; never paraphrase inside quotation marks.

### RULE#2 One-sentence summary first
Open with one sentence (25 words max) that carries the point, then the detail.

### RULE#3 Search before you create
Look for an existing note first; update or link it rather than duplicating.

### RULE#4 Never edit raw sources
Clippings and source files stay untouched; summaries are separate notes that link back.

## Defaults
- Summary: one-sentence summary → main points (up to 10, 16 words each max) → takeaways (up to 5). Scale to the source's length.
- Extraction: ideas, insights, quotes, facts, references, recommendations; include only the sections that have content.
- Compress by densifying: keep the length, add missing key entities, cut filler (chain of density).
- A summary must make sense without the source.
- Atomic notes: one idea per note, titled with the idea.
- Markdown and link format: [[NEOCORTEX/MECHANICS|MECHANICS]].
- Frontmatter on new knowledge notes: `type`, `tags`, `created: YYYY-MM-DD`, `source`.
- Keep folders shallow. Rules go in NEOCORTEX; project facts go in `PREFRONTAL/PROJECTS/<Project>/`.
- Ingesting a source: write the summary note, link it from the right hub, update related notes.
- On request, lint the vault: contradictions, stale claims, orphans, missing links.

## Avoid
- Meta-filler ("This article discusses…").
- Uncited claims, repeated points, empty sections.
